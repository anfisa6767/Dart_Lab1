## Ответы на контрольные вопросы

### 1. Чем статическая типизация Dart отличается от Python? Какое практическое преимущество она даёт?
В Python типизация динамическая: переменная может быть сначала числом, а потом строкой, и все ошибки вылезают уже во время работы программы. В Dart типизация статическая и строгая — тип переменной жестко проверяется еще во время компиляции, до запуска. 
**Главный плюс:** Компилятор сразу бьет по рукам, если ты пытаешься засунуть строку туда, где должно быть число. Ошибки отлавливаются еще на этапе написания кода в VS Code, а не тогда, когда программа уже запущена.

### 2. Что означает String? Чем отличается от String?
* `String` — это обычная строка, которая гарантированно не может быть пустой (`null`). Если попытаться записать туда `null`, код просто не скомпилируется.
* `String?` — это nullable-тип (знак вопроса как раз разрешает хранить `null`). 
**Отличие:** С обычным `String` можно работать сразу, а вот если у переменной тип `String?`, Dart заставит сначала сделать проверку (например, через `if` или операторы `?.` / `??`), чтобы программа случайно не упала при вызове методов.

### 3. Зачем в Dart final, если в Python можно просто договориться не менять переменную?
В Python константы держатся только на честном слове разработчиков — мы просто пишем имя капсом (типа `PI = 3.14`) и надеемся, что никто его не перезапишет. Но язык это никак не контролирует.
В Dart ключевое слово `final` защищает переменную на уровне компилятора. Если один раз присвоить значение, изменить его дальше уже физически не получится — проект выдаст ошибку компиляции. Это делает код надежнее, особенно в больших проектах.

### 4. Чем именованный параметр {required String name} отличается от позиционного? Приведите пример вызова.
Обычные позиционные параметры нужно передавать строго по порядку, который указан в функции. А именованные параметры пишутся в фигурных скобках `{}`. Ключевое слово `required` делает такой параметр обязательным. При вызове функции нам нужно прямо написать имя этого параметра, зато порядок передачи можно вообще не соблюдать.
**Пример вызова функции:**
`describePet(name: 'Барсик', species: 'кот', age: 3);`
